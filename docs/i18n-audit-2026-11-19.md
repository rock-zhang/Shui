## 三、P1 — 功能性问题（建议修）

### P1-1　多窗口语言不同步
**位置**：`src/lib/i18n/provider.tsx:54-121` + `src-tauri/src/core/window/macos.rs:79` / `windows.rs:46`
**证据**：前端全仓无 `storage` / `store://change` 监听（监听只在 Rust 侧 `lib.rs:132`）。`I18nProvider` 每个 window 各自实例化；提醒窗口创建后隐藏复用（`get_webview_window` 命中即 `show()`）。主设置窗口切换语言后，已存在但隐藏的提醒窗口仍持有旧 locale，下次提醒弹出仍是旧语言。
**建议**：provider 增加 `window.addEventListener("storage", …)`；Tauri 环境再监听 `listen("store://change", …)`，收到 `language` 变化后重新读取并 `setPreferenceState`。浏览器预览降级为前者。

### P1-2　首次启动时前端与 Rust 回退策略不一致
**位置**：`src/lib/i18n/locales.ts:48-56` vs `src-tauri/src/localization.rs:86,101-105`
**证据**：新装 / 清除数据后无 `language` 键时——前端 `readStoredPreference()` 返回 `"system"`，英文系统下解析为 `en-US`（UI 英文）；Rust `refresh_from_store()` 对 `None` 用 `.unwrap_or(Locale::Zh)`（托盘 / 桌面通知中文）；Kotlin 回退 `system` → `Locale.getDefault()`（英文，与前端一致）。结果是**英文系统新用户的界面是英文、托盘和通知是中文**。
**建议**：Rust 的 `None` / 非法值回退改为 `detect_system_locale()`，与前端 `system` 语义对齐；同时更新 `resolve_preference` 的测试断言（当前 `localization.rs:341-344` 断言 `None → Zh`）。

### P1-3　饮水明细时间格式不跟随 App 语言
**位置**：`src/components/drink-details.tsx:55`
**证据**：`new Date(entry.timestamp).toLocaleString()` 是全项目唯一不带 locale 的格式化调用（其余 `today-tab.tsx:487`、`notification-health-card.tsx:54` 等都传了 `locale`）。英文界面 + 中文系统下明细时间仍显示中文格式。
**建议**：改用 `formatTimeLabel(entry.timestamp, t("common.details.unknownTime"), locale)`（`@/lib/mobile` 已导出）。

- **Rust**：托盘状态 / tooltip、通知、文件对话框、提醒文案池均已本地化。命令返回的中文 `Err`（`data_backup.rs` 约 20 条、`mobile.rs` 等）有两道防线：备份链路走 `backupError` 方案1（英文界面回退通用提示、原文只进 console），其余前端 invoke 的 catch 全部用 `t()` 固定文案（已逐一核查 `setting/page.tsx`、`today-tab.tsx`、`health-card.tsx` 等 16 处 `toast.error`，无一处直接展示 `error.message`）。锁屏/解锁、窗口尺寸等中文仅进 `println!` 日志，非 UI。白名单应用名「腾讯会议」是真实应用名，保留正确。
