# 饮水记录备份与导入

本分支基于已合入外观主题、饮水记录、统计分析及 CSV 导出的 `main`，新增 JSON 备份与导入页面；这些已合入能力会继续保留。

在「备份与导入」页面导出 JSON 备份，或选择之前导出的文件进行预览。点击「确认导入缺失日期」才写入记录；取消选择或取消预览不会修改本地数据。

导入只新增本地不存在的日期。已有日期整天跳过，不合并该日明细、不重复累加，也不覆盖已有水量。确认时再次检查，因此预览之后新增的日期也会跳过。重复提交同一次确认返回已有结果，不重复写入；保存失败保留预览，允许重试。

## 数据范围

- 保留旧版数字总量，以及新版每日总量、历史目标、时间明细、请求 ID 和撤销标识。
- 支持本功能的 JSON 格式，最大 16 MB。不支持 CSV 导入。
- 备份文件不包含应用配置、主题选择或提醒统计，不是整个应用目录的备份。
- 预览使用选择文件时校验通过的数据；之后修改原文件，需要重新选择才会读入修改内容。
- 日期、非负整数总量、目标、时间、逐笔水量与总量一致性，以及重复或已撤销请求标识均会校验。未知版本、重复日期或非法数据不导入。
- 复用上游已有的饮水记录模型和写入锁，可与手动补记、明细撤销、主题及统计功能共同使用。导入后重新进入或刷新统计页查看结果，CSV 导出也会读取导入后的饮水记录。
- 导入只更新饮水记录，不修改现有的提醒统计、应用配置或主题选择。

备份格式版本 1：

```json
{
  "format": "shui-drink-backup",
  "version": 1,
  "exportedAt": "2026-11-06T12:00:00+08:00",
  "drinkHistory": {
    "20261104": 800,
    "20261105": {
      "schemaVersion": 1,
      "total": 900,
      "goal": 1500,
      "entries": [
        { "amount": 100, "timestamp": "2026-11-05T09:00:00+08:00", "requestId": "manual:example" }
      ],
      "revokedRequestIds": ["manual:revoked-example"]
    }
  }
}
```

## 写入与故障处理

导入与正常记水、明细撤销共用写入锁。启动时关闭饮水 Store 的延迟自动保存，避免旧的自动保存覆盖导入结果。导入先在同目录临时文件中写完并同步，再替换记录文件，成功之后才更新内存。备份导出会拒绝覆盖应用自身的记录或配置文件。写入和替换失败时保留原文件，并清理临时文件。

若本地文件损坏或被外部程序修改，导入会停止，不用空内存覆盖原文件。此时应先保留原文件，再处理损坏或重新启动以加载外部修改。此实现没有提供多进程文件锁，也不承诺断电后的事务恢复。
